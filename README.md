# 물리 법칙 수정형 2D 로그라이크 — 개발 현황

> Unity 기반 2D 플랫폼 로그라이크 / 덱 빌딩 게임. 플레이어가 카드 조합을 통해 이동·점프·중력 등의 게임 규칙을 바꾸는 것이 핵심 플레이.

**문서 상태:** 리팩터링을 위한 초안 (2026-11-17). 현재까지 공유된 `MapManager`, `RoomMaker`, 카드·적 생성 코드와 기능 설명을 토대로 작성. 프로젝트 전체 소스 파일 및 Inspector 구성은 아직 감사하지 않았으므로, 일부 인터페이스는 **제안**이지 구현 완료를 뜻하지 않음.

## 지금까지 동작한 주요 기능

- `MapTree`의 방 노드 그래프 및 `MapManager`의 방 이동·진행 관리
- `RoomMaker`의 플랫폼/문 타일맵 생성, `RoomData`에 방 구조 저장 및 재진입 시 복원
- `RoomEnemySpawner`의 방별 적 배치, 적의 감지/추적/공격, 테스트용 C키 적 처치 및 방 클리어 흐름
- 카드 생성·선택·인벤토리와 일렬 연결(`parentCard`/`childCard`) 및 물리 계수 적용 시도
- 지도/미니맵 및 문 기반 방 이동

위 항목은 **기능 흐름의 존재**를 의미한다. 버그 수정·리팩터링 완료를 의미하지 않는다.

## 다음 마일스톤: 플레이 가능한 코어 안정화

1. **진행 불능 제거:** 점프 가능 경로 검증, 빠른 이동 시 충돌, 바닥 판정 안정화
2. **방 이동 완성:** 문 접근 시 목적지 표시, Space로 이동, 입장한 방향의 문에서 스폰
3. **매니저/상태 정리:** 책임·의존성 문서화, `RoomData` 단일 원본화, 씬 Hierarchy 정리
4. **플랫폼 개선:** 넓고 두꺼운 복셀형 지형, 적이 떨어지지 않도록 순찰/추적 경계 설정
5. **카드 구조 개선:** 카드 효과 데이터와 UI 표현 분리, 연결 해제 복구, 카드 조합 표시 개선
6. **새 콘텐츠:** 나머지 카드, 물리 적용 주체 카드, 적 유형, 숫자 카드 밸런스

## 개발 원칙

- `MapManager`는 **언제 방을 생성/이동/클리어할지** 결정한다. 플랫폼을 직접 그리거나 적의 위치를 계산하지 않는다.
- `RoomMaker`는 **방의 공간 데이터 생성과 타일/문 렌더링**을 담당한다. 추후 커지면 내부 `RoomLayoutGenerator`/`RoomRenderer`로 분리한다.
- `RoomEnemySpawner`는 **어떤 적을 어디에 생성할지** 처리한다. 방 진행 여부는 `MapManager`가 결정한다.
- `CardManager`는 **카드 생성/선택**, `CardCombinationManager`는 **합성 검증/연결**, `UIManager`는 현재 설계에서 **인벤토리 보유 및 화면 표시**를 담당한다.
- 게임 규칙 계산은 카드 UI에 두지 않는다. 카드 구성과 물리 계수는 다시 계산해 적용한다.
- 방/카드/플레이어 상태는 가능한 한 **한곳에서 소유**하고, UI는 그 결과를 표시한다.
- 수정마다 **재현 조건 + 완료 기준 + 테스트**를 남긴다. 플레이 불가능한 랜덤 시드를 재현할 수 있도록 시드 기록을 도입한다.

## 주의할 현재 이슈

- `RoomMaker.MaxJumpDistance`, `MaxJumpHeight`가 정의되어 있으나 제공된 코드에서는 경로 보장에 사용되지 않음.
- `RoomMaker.DrawPlatforms()`는 플랫폼당 한 줄의 타일만 배치하며 폭은 기본 5~9칸.
- 문의 재진입 위치는 제공된 `MapManager` 코드에서 항상 생성 시작 플랫폼을 사용했음.
- 카드 조합이 일렬 체인이라는 사실을 유지해야 함. 스크래치형 UI = 데이터 트리로 확장하는 것을 뜻하지 않음.
- **실제 프로젝트 최신 코드 전체를 보기 전에는 리팩터링의 상세 변경 범위를 확정하지 말 것.**
