# 리팩터링 로드맵 및 작업 티켓

**버전:** 초안 2026-11-17. 번호는 권장 순서, 상태는 모두 **미검증/작업 예정**이다. 실제 소스 최신 버전을 검토하면서 체크한다.

## 우선순위 원칙

- **P0 — 플레이 진행 불가/상태 중복/데이터 손상:** 다른 기능보다 먼저
- **P1 — 확장 전 구조 정리:** 카드/적 유형이 늘어나기 전에
- **P2 — UX와 지형 품질:** 플레이 흐름의 일관성 강화
- **P3 — 콘텐츠 및 수치 밸런스:** 안정화 후

## Phase 0 — 기준선과 버그 재현 (P0)

| ID | 작업 | 완료 기준 |
|---|---|---|
| R-01 | 현재 구조/호출 관계·실제 클래스·프리팹 참조 감사 | 각 매니저 진입점/소유 데이터/참조 방향 표와 누락된 Inspector 참조 목록 확보 |
| R-02 | Hierarchy 정리 및 프리팹/씬 참조 확인 | Managers/World/UIRoot 정리, 플레이 모드에서 참조 유실 0건 |
| R-03 | 랜덤 방 재현 시드와 디버그 정보 추가 | 실패한 방의 시드·노드·발판·플레이어 이동값을 기록해 동일 맵 재현 가능 |

## Phase 1 — 진행 안정성 (P0)

### R-04 빠른 플레이어 벽 통과 방지
- 현재 이동 코드가 `transform.position` 직접 변경, FixedUpdate 외 Rigidbody2D 변경, 충돌 탐지 방식에 의존하는지 확인.
- 플레이어 Rigidbody2D의 **Collision Detection = Continuous** 시험; 이동은 Rigidbody2D를 일관되게 사용. 적절한 레이어·TilemapCollider2D/CompositeCollider2D·콜라이더 두께 확인.
- 극단적 카드 효과에서는 이동 전 `Collider2D.Cast`류의 예측 검사 또는 계수 상한/이동 방식 보완 검토.
- **완료 기준:** 기본/1.5배/2배/상한 테스트 이동 속도에서 벽 통과 0건, 방 입장 직후 충돌 정상.

### R-05 접지·점프 판정 안정화
- '순간적인 수직 충돌 이벤트'에만 의존하는 접지 판정 제거.
- 매 `FixedUpdate`에서 발 부근 `OverlapBox` 또는 `Collider2D.Cast`로 Ground Layer 확인; `coyoteTime`과 `jumpBufferTime` 소량(예: 0.1초) 도입 검토.
- 벽/천장 접촉은 Ground로 인정하지 않고, 중력 반전 카드가 있다면 바닥 방향 개념도 함께 설계.
- **완료 기준:** 경사/모서리/착지 직후에도 의도한 점프 입력이 누락되지 않음; 공중에서 무제한 점프는 불가.

### R-06 진행 가능한 플랫폼 배치 보장
- `MaxJumpDistance`·`MaxJumpHeight`를 실제 점프 가능성 검사에 연결.
- 플랫폼 가장자리·고저 차·발판 폭을 고려한 유향 접근 그래프를 만들고 시작점→필수 문까지 BFS/DFS 검증.
- 실패 시 배치 재생성 또는 연결 발판 보강; 재현 시드 기록.
- **완료 기준:** 최소 100개 시드를 자동 생성해 모두 시작점에서 필수 출구 도달 가능(기본 플레이어 계수 기준).

### R-07 방 이동/스폰 양방향 복원
- 문 `OnTriggerEnter`에서 이동 금지; 후보 문 표시 및 **Space** 키 입력 시 이동.
- `Door.targetNode`와 `previousNode`를 전달, 목적지 방에서 `targetNode == previousNode`인 문을 찾아 해당 문의 안전 스폰 마커로 출현.
- 목적지 연결이 한쪽 방향인 맵은 역방향 입구 데이터 별도 생성. 이동 직후 속도 초기화/입력 잠금과 문 트리거 재진입 방지.
- **완료 기준:** A↔B 왕복 시 항상 해당 문에서 안전하게 출현; Space 전에는 이동하지 않음.

### R-08 방 상태/보상 중복 방지
- `RoomData.isGenerated`, `isCleared`, `isRewardClaimed`를 분리.
- 클리어 방 재입장 시 적 0·문 열림·보상 중복 없음; 적 없는 시작/보상 방은 별도 정책.
- **완료 기준:** A→B→A→B 반복해도 적·보상·클리어 이벤트 중복 없음.

## Phase 2 — 구조와 지형 개선 (P1/P2)

### R-09 매니저 역할 명확화
- `MapManager`: 방 진행만, `RoomMaker`: 공간 데이터/렌더링, `RoomEnemySpawner`: 실제 적 인스턴스, `CardManager`: 후보 생성/선택, `CardCombinationManager`: 합성 검증, `UIManager`: 현행 인벤토리·UI.
- GameManager가 모든 시스템을 직접 실행하지 않도록 한다.
- **완료 기준:** 각 기능에 유일한 진입점/책임 소유자가 있고, 순환 호출이 문서화/제거됨.

### R-10 방 생성 파이프라인 분리
- 현재 `RoomMaker`에 몰려 있는 좌표 생성/플랫폼 타입/적 후보/타일 렌더링을 내부 메서드 또는 별도 구성 요소로 단계별 분리.
- 한 번 생성한 결과는 순수 `RoomData`에 저장; 렌더러는 데이터만 보고 다시 그린다.
- **완료 기준:** 동일 RoomData로 재진입하면 지형·문 위치가 불변.

### R-11 두껍고 넓은 복셀형 플랫폼
- 플랫폼을 단일 가로줄 대신 **여러 기준점 연결 → 상면 형성 → 아래쪽 영역 채움**으로 구성.
- 적이 순찰할 수 있는 최소 폭·경계, 문에 필요한 안전 폭을 따로 둔다.
- 접하는 타일의 형태를 상단/측면/내부로 구분해 시각적 두께 표현. TilemapCollider2D + CompositeCollider2D 검토.
- **완료 기준:** 적이 플랫폼 끝으로 무작정 낙하하지 않고, 발판 폭과 두께가 화면에서 읽힘.

### R-12 적 추적 안전성
- 추적 전에 지면/끝 감지(`groundAhead`)를 추가; 단순 거리 추적과 분리.
- 상하 플랫폼 이동을 할 적과 현재 플랫폼을 지킬 적을 역할/AI 타입으로 분리하는 정책 초안 작성.
- **완료 기준:** 일반 근접 적은 낭떠러지에서 추적을 멈추거나 돌아서며, 추적 해제 거리에서 정상 복귀.

## Phase 3 — 카드 데이터·UI 리팩터링 (P1/P2)

### R-13 CardInstance 타입/효과 모델 재정의(부분 완료)
- `CardInstance` 한 클래스에 숫자·물리·스탯·특수효과 필드가 모두 모인 상황 개선.
- 공통 인스턴스 ID + 종류별 데이터(서브클래스 또는 효과 객체) 도입 여부 설계.
- 기존 `parentCard`/`childCard` **선형 체인** 및 유효성/순환 방지는 유지.
- **완료 기준:** 새 카드 종류를 추가할 때 기존 클래스의 무관한 필드를 대거 수정할 필요 없음.
- 현재 CardInstance를 필드가 상속하는 인터페이스로 변경 후 필드별 스크립트로 분리함.

### R-14 카드 평가와 적용 주체 분리
- 카드 UI→게임 계산 직접 호출 제거; `CardEffectEvaluator`가 체인에서 대상/속성/연산을 판정하고 `EffectApplier`가 물리값에 반영.
- 기본 물리 값에서 전체 재계산; 연결 해제·방 이동·적 스폰 시 재적용.
- **완료 기준:** UI 없이 카드 효과 계산 단위 테스트 가능; 중복 적용/누락 없음.

### R-15 스크래치형 합성 카드 시각화
- 새 CardInstance를 복제하지 않고 기존 체인을 순서대로 화면에 표시.
- 블록 연결부/들여쓰기·상단/하단 시각 모양·연산 기호·드래그 영역 정리.
- **완료 기준:** `Gravity→×2→+3`을 합성 카드 한 장으로 보고 연결 순서가 분명함.

### R-16 카드 연결 해제 버튼 오류 수정
- `CombinedBlockUI`의 버튼 이벤트·참조·Raycast/CanvasGroup·UI 재생성 시점 확인.
- 중간/끝 연결을 끊은 뒤 인벤토리 루트 목록, 드래그 가능 여부, 물리 값이 즉시 정상 갱신되는지 검사.
- **완료 기준:** `A→B→C`에서 `B` 해제 시 `A`와 `B→C`, `C` 해제 시 `A→B`와 `C`가 각각 표시/조작 가능.

### R-17 물리 적용 주체 카드
- 체인 규칙 예시: `EnemyTarget → GravityScale → ×2` / 주체 카드가 없으면 Player 기본.
- 루트 카드가 물리 카드라는 기존 평가 가정 제거, 적마다 고유 기본 중력 보존.
- **완료 기준:** EnemyTarget 카드가 붙은 중력 효과는 적만 변경, 플레이어는 바뀌지 않음.

### R-18 미구현 카드 효과 추가
- 구현 목록부터 작성(Stat/Physics/특수 등), 각 카드에 적용 대상·중첩·범위·클램프·UI 표현 계약 정의.
- **완료 기준:** 카드 타입마다 생성/조합/적용/해제 테스트가 있음.

## Phase 4 — 미니맵·UI 경험 (P2)

### R-19 미니맵 줌
- 휠 입력/스케일 변경/기준점/최소·최대값을 점검해 축소·확대 모두 제공.
- 확대 중심을 플레이어/커서 중 하나로 고정, 초기화 버튼 또는 단축키 지원.
- **완료 기준:** 축소/확대/리셋이 반복되어도 노드 위치가 드리프트하지 않음.

### R-20 노드 hover 경로 강조
- `MapTree.Node.connections`의 관계를 이용해 해당 노드에 붙은 Edge UI만 강조하고, 커서 이탈 시 복원.
- 미니맵(또는 전체 지도)의 `GraphicRaycaster`, `Raycast Target`, 연결 UI 데이터 구조 점검.
- **완료 기준:** 노드 hover 시 연결 간선만 강조되고 다른 간선은 정상 복귀.

### R-21 문 목적지 프롬프트
- 문에 가까울 때 `이동: {nodeType} — Space` 표시, 트리거 벗어나면 숨김.
- 카드 선택/인벤토리/일시정지 중 Space 입력과 충돌하지 않도록 UI 포커스 규칙 정의.
- **완료 기준:** 문 접촉만으로 이동하지 않고, 목적지 노드 표시가 정확함.

## Phase 5 — 콘텐츠·밸런스 (P3)

### R-22 숫자 카드 보상 희귀도 조정
- 체감 실험을 기준으로 `×2` 근처를 강한 보상으로, `×1.5` 이하를 일반 보상 후보로 우선 설계.
- 연산자/기본 능력치에 따라 성능 차이가 커지므로 **숫자 크기만으로 희귀도를 정하지 않는다**. 예: 중력 `×0.5` 역시 체감이 클 수 있음.
- common/hard/elite/reward 카드 풀과 가중치/범위 정의 후 플레이 테스트.
- **완료 기준:** 각 풀의 숫자 값 분포와 체감 효과를 표로 기록하고 지나친 성능 폭주가 없음.

### R-23 적 종류 추가
- 적 공통 베이스(생존·상태·타깃·공통 공격 인터페이스)를 안정화한 뒤 빠른 적, 고정형 적, 점프 가능 적 등 행동 차이로 확장.
- **완료 기준:** 새 적 추가 시 기존 `MapManager`/`RoomMaker`를 수정할 필요가 없음.
