# PatchNote — 리팩터링 로드맵 및 작업 체크리스트

> **기준:** GitHub `master` (`8a0e951`, 2026-11-28 확인)  
> **작업 관리:** 항목마다 `- [ ]` / `- [x]`를 사용한다. **코드 반영**과 **Unity 테스트 통과**는 별개 항목으로 기록한다.  
> **상태 해석:** `[x]`는 확인 가능한 코드·씬 반영 또는 직접 확인된 완료 작업만 의미한다. Play Mode·빌드 결과를 확인하지 않은 테스트는 `[ ]`로 남긴다. 티켓 제목에 *부분 진행*이 있더라도 모든 하위 체크를 마쳐야 전체 완료다.

## 작업 우선순위

- **P0:** 플레이 진행 불가, 방·보상 상태 이상, 데이터 무결성
- **P1:** 확장 전에 책임·데이터 구조 정리
- **P2:** UI/UX 및 지형·맵 표현 개선
- **P3:** 카드 밸런스, 적·무기 콘텐츠 확대

## Phase 1 — 진행 안정성 (P0)

### R-04 · 빠른 플레이어 벽 통과 방지
- [ ] 이동 코드의 `transform.position` 직접 변경·Rigidbody2D 조작 위치를 점검한다.
- [ ] `Rigidbody2D` Collision Detection의 `Continuous` 적용을 시험한다.
- [ ] Layer/TilemapCollider2D/CompositeCollider2D 및 콜라이더 두께를 검증한다.
- [ ] 극단적 카드 효과에 대한 `Collider2D.Cast` 예측 검사·계수 상한을 검토한다.
- [ ] **완료 기준:** 기본·1.5배·2배·상한 속도에서 벽 관통 0건, 방 진입 직후 충돌 정상.

### R-05 · 접지·점프 판정 안정화
- [ ] 순간적인 충돌 이벤트에만 의존하는 접지 상태를 제거한다.
- [ ] `FixedUpdate`에서 발 영역 `OverlapBox` 또는 `Collider2D.Cast`로 지면을 확인한다.
- [ ] `coyoteTime`·`jumpBufferTime`(예: 각각 0.1초) 도입 여부를 검토한다.
- [ ] 벽/천장 접촉과 중력 반전 시의 접지 방향 정책을 확정한다.
- [ ] **완료 기준:** 착지·모서리·경사에서 입력 누락이 없고 의도치 않은 무한 점프 불가.

### R-06 · 이동 가능한 플랫폼 배치 보장
- [ ] `MaxJumpDistance`, `MaxJumpHeight`를 실제 판정에 사용한다.
- [ ] 플랫폼 가장자리·고저 차·너비·플레이어 콜라이더를 고려한 유향 접근 그래프를 만든다.
- [ ] 시작점에서 필수 문까지 BFS/DFS 등으로 도달 가능성을 검사한다.
- [ ] 실패 시 방 재생성 또는 보조 발판 배치 규칙을 도입한다.
- [ ] **완료 기준:** 기본 물리값으로 고정 시드 100개에서 필수 출구 도달 가능.

### R-07 · 방 이동/입장 스폰 양방향 복원
- [ ] `Door` 접촉만으로 즉시 이동하지 않도록 상호작용 입력을 분리한다.
- [ ] 문 대상과 직전 방 노드를 `MapManager`에 함께 전달하는 API를 설계한다.
- [ ] 도착 방에서 **이전 노드로 향하는 문** 근처의 안전 스폰 위치를 찾는다.
- [ ] 역방향 연결이 없는 경우 명시적 입구 마커를 제공한다.
- [ ] 이동 중 재입력 차단·속도 초기화·문 트리거 중복 이동 방지를 적용한다.
- [ ] **완료 기준:** A↔B 반복 왕복 시 매번 대응 문에서 등장하고 입력 전에는 이동하지 않음.

### R-08 · 방 상태·보상 중복 방지
- [ ] `RoomData`의 `isGenerated`, `isCleared`, `isRewardClaimed` 역할을 분리한다.
- [ ] 클리어 방 재방문 시 적 생성·보상 지급·문 상태를 복원한다.
- [ ] 시작·보상·보스 노드의 클리어·보상 정책을 각각 확정한다.
- [ ] **완료 기준:** A→B→A→B 왕복에서 적·보상·클리어 이벤트 중복 0건.

## Phase 5 — 콘텐츠와 밸런스 (P3)

### R-22 · 숫자 카드 보상 희귀도 조정
- [ ] 약 ×2는 강한 보상, ×1.5 이하는 일반 보상 후보라는 기존 플레이 체감을 데이터로 재검증한다.
- [ ] 속성·연산자(예: 중력 ×0.5)에 따른 체감 차이를 별도 기록한다.
- [ ] common/hard/elite/reward/boss 풀별 가중치와 수치 범위를 조정한다.
- [ ] **완료 기준:** 카드 풀별 분포와 체감 성능 기록이 있고 극단적인 성능 폭주가 없음.

### R-23 · 적 종류 추가
- [ ] 공통 적 생존·상태·공격 계약을 먼저 정한다.
- [ ] 빠른 적·고정형·점프형 등의 행동 차이를 설계한다.
- [ ] 신규 적 추가 시 기존 맵·지형 관리 코드를 수정할 필요가 없는지 확인한다.
- [ ] **완료 기준:** 새 적 타입이 기존 방 스폰 시스템에 독립적으로 등록·동작함.

## 필수 회귀 테스트

> 테스트한 사람·날짜·Unity 버전·사용한 씬과 결과를 PR이나 커밋 설명, 또는 테스트 로그에 남긴다. 검증 전에는 체크하지 않는다.

- [ ] 기본·1.5배·2배·상한 이동 속도에서 벽 관통 0건.
- [ ] 착지 직전·순간·모서리 점프 입력이 정상적으로 처리됨.
- [ ] 고정 시드 100개에서 필수 문까지 도달 가능.
- [ ] 문 가까이 있어도 상호작용 전에는 이동하지 않음.
- [ ] A ↔ B 반복 왕복 시 맞는 문에서 등장함.
- [ ] 클리어된 방 재입장 시 적·보상·클리어 이벤트 중복 없음.
- [ ] `A → B → C` 중간·끝 카드 해제 후 화면·데이터가 일치함.
- [ ] 합성 카드 드래그 중/이후 UI 갱신 시 예외 없음.
- [ ] Target 카드 적용 시 World·Player·Enemy 적용 범위가 분리됨.
- [ ] 미니맵 줌 인/아웃/리셋 및 연결 간선 Hover 강조가 정상임.
- [ ] 적이 기본 지형에서 의도치 않게 낙하하지 않음.

```md
- 관련 커밋: <SHA>
```

### 커밋 메시지 규칙

**형식:** `[작업 종류] 세부 내용`  
예시: `[Update Docs] 리팩터링 체크리스트 및 매니저 구조 문서 정리`

- `[Add Script]` : 새 스크립트 추가
- `[Fix Bug]` : 실제 오류 수정
- `[Refactor Script]` : 기능 의도를 유지한 코드 구조 정리
- `[Amend Scene]` : 씬·Hierarchy·프리팹 참조 수정
- `[Update Docs]` : 설계·기획·진행 문서 갱신
- `[Add Feature]` : 신규 기능 구현

**작업 방식:** ChatGPT는 로컬 적용용 변경 파일·설명을 제공한다. 사용자가 Unity에서 확인하고 직접 Commit·Push한다. 기능 단위로 변경을 묶고, 테스트되지 않은 기능을 완료 처리하지 않는다.
